# 部门四：质检部 (Quality Gate)

> 五关验证规范，防御低质量交付/越界/幻觉/空转

---

## 防御对象

| 故障类型 | 表现 | 防御机制 |
|---------|------|---------|
| ① 低质量交付 | 成果粗制滥造、缺项 | 验收清单逐项打勾，缺项打回 |
| ② 无视边界 | 越权操作、超范围执行 | 权限矩阵操作前校验 |
| ③ 幻觉 | 编造结果、虚假证据 | 证据链验证：无法验证 = 判无效 |
| ④ 恶性空转 | 反复重试无进展、烧Token | 空转检测：N次无进展自动上报 |

---

## 五关验证流程

```
① 交付质量关（QA：验收清单逐项核对）
  → ② 边界合规关（QA：权限审计，越权即拦截）
  → ③ 证据验证关（QA：文件/测试/URL 实检，防幻觉）
  → ④ COO 复审（质量标准验收 + 总结报告 + 汇总）
  → ⑤ CEO 终审（老板拍板决策）
```

---

## 各关执行标准

### ① 交付质量关
- 对照任务卡验收标准逐项核对
- 缺项/不达标 → 打回执行岗重修（最多 N 次）

### ② 边界合规关
- 检查产出是否越出岗位权限矩阵
- 越权操作 → 立即拦截，上报 COO

### ③ 证据验证关（防幻觉核心）
- 所有"完成"声明必须附可验证证据：
  - 文件交付 → 文件真实存在且内容可读
  - 功能实现 → 测试真实执行通过
  - 外部信息 → URL/数据源可访问
- 无法验证 = 判无效，打回

### ④ COO 复审
- 质量标准终验 + 总结报告 + 汇总
- 输出固定格式：任务/级别/指令回放/交付物+证据/成本/偏差/建议

### ⑤ CEO 终审
- 老板拍板：采纳 / 打回 / 调整

---

## 空转检测

| 信号 | 动作 |
|------|------|
| 同任务 N 次重试无实质进展 | 自动上报 CEO 换方案 |
| Token/费用超预算 80% | 预警 |
| 超过 100% | 强制暂停，等老板决策 |

---

## 验证清单模板

```
【任务卡号】________
[ ] 交付物存在且完整
[ ] 与原始指令一致（无偏移）
[ ] 证据链可验证（文件/测试/URL）
[ ] 未越出岗位权限
[ ] 成本在预算内
[ ] QA 判定：PASS / 打回（原因：____）
[ ] COO 复审：通过 / 驳回
[ ] CEO 终审：采纳 / 打回
```
